1. Pourquoi une fonction

La même chose, écrite une fois :

Python
12345
def grouper_par(lignes, cle):
    resultat = {}
    for ligne in lignes:
        resultat[ligne[cle]] = resultat.get(ligne[cle], 0) + ligne["montant"]
    return resultat
Python
123
par_departement = grouper_par(ventes, "departement")
par_produit = grouper_par(ventes, "produit")
par_categorie = grouper_par(ventes, "categorie")      # gratuit

Regardez la troisième ligne. Le regroupement par catégorie n'était demandé nulle part, et il n'a coûté aucune ligne de code. C'est ça, une fonction : pas une décoration, un gain.

La syntaxe, à côté de ce que vous connaissez

C / C++ PHP Python
Déclaration int f(int a) function f($a) def f(a):
Type de retour Déclaré Facultatif Aucun
Types des paramètres Déclarés Facultatifs Aucun
Corps Entre accolades Entre accolades Indenté
Retour return return return

En Python, on ne déclare aucun type. La fonction accepte ce qu'on lui donne et ne se plaint qu'à l'exécution — d'où l'importance du module 4.

Si vous n'avez jamais écrit de fonction, retenez ceci et rien d'autre pour l'instant : une fonction, c'est un bout de programme qu'on nomme, pour pouvoir le redemander plus tard sans le réécrire.

Le return oublié

C'est l'erreur numéro un quand on débute en Python.

Python
12345
def moyenne(notes):
    print(sum(notes) / len(notes))      # print, pas return

m = moyenne([10, 20])
print(m + 1)
Code
123456
15.0
Traceback (most recent call last):
  File "moyenne.py", line 5, in <module>
    print(m + 1)
          ~~^~~
TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'

Le 15.0 s'est bien affiché : le calcul était juste. Mais la fonction n'a rien renvoyé, donc m vaut None, et l'addition casse une ligne plus loin.

print montre. return donne.

Une fonction qui affiche au lieu de renvoyer ne peut pas être utilisée par une autre fonction. Retenez cette phrase, elle vaut le reste de la page.

Toute fonction Python renvoie quelque chose. Sans return, elle renvoie None. C'est exactement pour ça que liste.sort() renvoie None — vous l'avez rencontré à la séance 2 sans savoir pourquoi.

3. Les paramètres

Valeurs par défaut et arguments nommés

Python
123456
def bulletin(nom, notes, avec_mention=True):
    moyenne = sum(notes) / len(notes)
    ligne = f"{nom} : moyenne {moyenne:.1f} sur 20"
    if avec_mention:
        ligne = f"{ligne} — mention {mention(moyenne)}"
    return ligne
Python
123
bulletin("Ana", [12, 17, 14])                          # Ana : moyenne 14.3 sur 20 — mention bien
bulletin("Luc", [15, 15, 15], avec_mention=False)      # Luc : moyenne 15.0 sur 20
bulletin(notes=[10, 10, 10], nom="Paul")               # l'ordre n'importe plus

Deux règles :

  • Un paramètre à valeur par défaut se place après ceux qui n'en ont pas. Sinon Python refuse le fichier : SyntaxError: non-default argument follows default argument.
  • Nommer l'argument à l'appel rend l'appel lisible. bulletin("Luc", notes, False) ne dit rien ; avec_mention=False dit tout.

PHP a les valeurs par défaut depuis toujours et les arguments nommés depuis PHP 8 — vous êtes en terrain connu. C++ a les valeurs par défaut mais pas les arguments nommés : c'est un gain net.

Renvoyer plusieurs valeurs

Python
12345
def statistiques(nombres):
    return min(nombres), max(nombres), sum(nombres) / len(nombres)

bas, haut, moyenne = statistiques([12, 17, 9, 14, 18, 7, 15])
print(bas, haut, moyenne)      # 7 18 13.142857142857142

C'est le tuple de la séance 2 : la fonction renvoie un seul objet, qu'on déballe à l'arrivée. Sans déballage, on obtient (7, 18, 13.142857142857142).

En C++ il faudrait une structure ; en PHP un tableau à ré-indexer. Ici, une virgule.

4. Lire un message d'erreur

C'est la partie de cette séance qui vous servira le plus souvent.

La règle : on lit un traceback par le bas

Code
1234567891011
Traceback (most recent call last):
  File "bulletin.py", line 8, in <module>
    print(bulletin("Ana", []))
          ^^^^^^^^^^^^^^^^^^^
  File "bulletin.py", line 5, in bulletin
    m = moyenne(notes)
        ^^^^^^^^^^^^^^
  File "bulletin.py", line 2, in moyenne
    return sum(notes) / len(notes)
           ~~~~~~~~~~~^~~~~~~~~~~~
ZeroDivisionError: division by zero
Où regarder Ce qu'on y trouve Ici
1. La dernière ligne Le type de l'erreur et son message ZeroDivisionError: division by zero
2. Le bloc juste au-dessus Le fichier, la ligne et le code où ça a cassé bulletin.py, ligne 2
3. Les flèches ^^^ ou ~~~^~~~ L'endroit exact dans la ligne la division
4. En remontant Qui a appelé qui <module> → bulletin → moyenne

Le réflexe à casser : lire de haut en bas et s'arrêter au premier File. Le premier File, c'est votre print — il n'a rien fait de mal. La ligne fautive est en bas.

Ici, la cause réelle n'est même pas à la ligne 2 : c'est la liste vide passée à la ligne 8. Le traceback vous donne les deux bouts de la chaîne, à vous de choisir lequel réparer.

Les flèches ^^^ n'existent que depuis Python 3.11, et la façon dont elles soulignent varie un peu selon la version. Si votre sortie diffère légèrement de celle d'un camarade, ce n'est pas une erreur d'installation. La dernière ligne et le numéro de ligne, eux, ne varient jamais.

Les huit erreurs que vous rencontrerez

Message Ce qui s'est passé Où chercher
NameError: name 'note' is not defined. Did you mean: 'notes'? Nom jamais défini — souvent une faute de frappe Lisez la fin de la ligne : Python vous souffle la réponse
TypeError: bonjour() missing 1 required positional argument: 'nom' Fonction appelée sans un de ses paramètres L'appel, pas la fonction
TypeError: unsupported operand type(s) for +: 'NoneType' and 'int' Vous utilisez le résultat d'une fonction qui ne renvoie rien Le return manquant
TypeError: unsupported operand type(s) for +=: 'int' and 'str' Un nombre et une chaîne mélangés Un input non converti, neuf fois sur dix
UnboundLocalError: cannot access local variable 'n' where it is not associated with a value Vous lisez une variable locale avant de lui donner une valeur La première ligne de la fonction
IndentationError / TabError Indentation incohérente, tabulations et espaces mélangés Réglez VS Code une fois : quatre espaces
KeyError: 'xxx' Clé absente d'un dictionnaire get(cle, defaut) — c'est la séance 2
ZeroDivisionError: division by zero Une liste vide dont vous calculez la moyenne len(...) vaut 0

La première mérite qu'on s'y arrête. Depuis Python 3.10, l'interpréteur propose une correction quand le nom ressemble à un nom existant. Beaucoup de gens ne lisent pas la fin de la ligne et passent à côté de la réponse écrite devant eux.

La portée : une variable de fonction reste dans sa fonction

Python
1234567
compteur = 0

def incrementer():
    compteur = 10
    return compteur

print(incrementer(), compteur)      # 10 0

Le compteur du dehors n'a pas bougé. Une variable créée dans une fonction n'existe que dans la fonction.

Et voici le symptôme quand on croit le contraire :

Python
123
def compteur():
    n = n + 1        # UnboundLocalError
    return n

Python voit une affectation à n dans la fonction, donc n est locale — et vous la lisez avant de l'avoir écrite.

La solution n'est pas de rendre la variable globale. C'est de passer la valeur en paramètre et de renvoyer le résultat.

def calculer_montants(lignes):

        ligne["montant"] = ligne["quantite"] * ligne["prix_unitaire"]

def grouper_par(lignes, cle, valeur="montant"):
    """Regroupe les lignes par 'cle' et somme le champ 'valeur'."""
    resultat = {}
    for ligne in lignes:
        resultat[ligne[cle]] = resultat.get(ligne[cle], 0) + ligne[valeur]

def afficher_tableau(titre, totaux, largeur=12):
    """Affiche un dictionnaire trié par valeur décroissante."""
    print(f"=== {titre} ===")
    for nom, montant in sorted(totaux.items(), key=lambda paire: paire[1], reverse=True):
        print(f"{nom:<{largeur}} {montant:>10.2f} HTG")
Python
1234567
calculer_montants(ventes)
afficher_tableau("Par département", grouper_par(ventes, "departement"))
afficher_tableau("Par produit", grouper_par(ventes, "produit"))
afficher_tableau("Par catégorie", grouper_par(ventes, "categorie"))

print(grouper_par(ventes, "departement", valeur="quantite"))
# {'Ouest': 615, 'Artibonite': 840, 'Sud': 510, 'Nord': 275}

La dernière ligne donne les quantités au lieu des montants, et elle a coûté un mot. Avec trois blocs copiés-collés, il aurait fallu en écrire un quatrième.

Les trois règles de découpage
1 Une fonction fait une chose. Si son nom contient « et », coupez-la en deux
2 Une fonction qui calcule ne devrait pas afficher. Une fonction qui fait les deux ne se réutilise pas
3 Le nom est un verbe. calculer_montants, grouper_par, afficher_tableau

À retenir de cette séance

  1. print montre, return donne. Une fonction sans return renvoie None
  2. Un paramètre à valeur par défaut se place après les autres ; nommer l'argument à l'appel rend l'appel lisible
  3. Une fonction peut renvoyer plusieurs valeurs — c'est un tuple, qu'on déballe
  4. Un traceback se lit par le bas : le type, puis la ligne fautive, puis qui a appelé qui

Le piège de la liste par défaut

Python
1234567
def ajouter(element, liste=[]):
    liste.append(element)
    return liste

print(ajouter("a"))     # ['a']
print(ajouter("b"))     # ['a', 'b']     ← !
print(ajouter("c"))     # ['a', 'b', 'c']

La liste par défaut est créée une seule fois, à la définition de la fonction : tous les appels partagent la même. C'est un cousin direct du b = a de la séance 1, et c'est le piège le plus célèbre du langage.

La correction :

Python
12345
def ajouter(element, liste=None):
    if liste is None:
        liste = []
    liste.append(element)
    return liste

Pourquoi pas au cours : il ne tombe que sur du code qui vit longtemps, et le temps manque. Mais vous le rencontrerez un jour, et vous aurez mis une heure à le trouver si vous ne l'avez jamais vu.

try / except — attraper une erreur

Python
12345
try:
    seuil = int(input("Seuil : "))
except ValueError:

Pourquoi ce n'est pas au cours : avec six séances, savoir lire une erreur vaut plus que savoir l'attraper — et attraper une erreur qu'on ne sait pas lire produit du code qui échoue en silence, ce qui est pire que du code qui plante. Où chercher : documentation Python, « Errors and Exceptions ».

*args et **kwargs

Une fonction qui accepte un nombre quelconque d'arguments. Vous l'avez déjà utilisé sans le savoir : print("a", "b", "c"). Où chercher : « arbitrary argument lists ».

Les annotations de type

Python
12
def moyenne(notes: list[float]) -> float:
    return sum(notes) / len(notes)

Python ne vérifie rien à l'exécution — c'est de la documentation exécutable, que VS Code utilise pour vous aider. Pourquoi pas au cours : ça ajoute une syntaxe sans rien changer au comportement. Utile dès que votre code dépasse deux cents lignes.

Les fonctions récursives

Une fonction qui s'appelle elle-même. Vous connaissez peut-être le principe en C++. En Python c'est identique, avec une limite de profondeur d'environ mille appels.
