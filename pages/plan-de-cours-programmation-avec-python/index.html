2. Présentation du cours

Si vous savez déjà programmer. Vous avez écrit du C, du C++ ou du PHP, vous connaissez les boucles, les fonctions, les classes. Ce cours ne va donc pas vous réapprendre à programmer : il va vous apprendre Python, et surtout vous préparer à ce qui vient ensuite.

Car ce cours a une suite. Le cours d'intelligence artificielle qui suivra se fera en Python, et il supposera acquises un certain nombre de choses : savoir installer un environnement et des bibliothèques, savoir charger et nettoyer un jeu de données, savoir manipuler des tableaux de nombres sans écrire de boucles, et savoir lire la documentation d'une bibliothèque qu'on n'a jamais utilisée. C'est exactement ce qu'on va construire ici.

Le cours est donc rapide sur ce que vous connaissez déjà et prend son temps sur ce qui est propre à Python : sa façon de manipuler les données, ses raccourcis d'écriture, et son écosystème scientifique.

Une mise en garde utile. Venant du C, du C++ ou du PHP, la tentation est d'écrire du Python avec les réflexes de ces langages. Ça fonctionne, mais c'est lent, verbeux, et illisible pour les autres. Une bonne partie du travail de ce cours consiste à désapprendre certains automatismes.

Place dans la formation. Ce cours prolonge les acquis en programmation des deux premières années et prépare directement le cours d'intelligence artificielle.

Prérequis. Avoir suivi un cours de programmation (C, C++, PHP ou équivalent) et un cours d'algorithmique. Aucune connaissance de Python n'est nécessaire.

Si vous n'avez jamais programmé, ou très peu : le module 0 contient un parcours de mise en route, non noté et non obligatoire, qui reprend variables, conditions et boucles depuis le début. Suivez-le avant la séance 1.

6. Détail des séances

Séance 1 - Python pour ceux qui programment déjà

  • Contenu du cours. Ce qui change par rapport au C/C++ et au PHP : typage dynamique, indentation significative, pas de compilation, pas de gestion mémoire, tout est objet. Les types de base et leurs pièges. Conditions et boucles : la syntaxe en accéléré, et surtout la boucle for qui parcourt directement les éléments plutôt que les index. Les conventions d'écriture (PEP 8). L'outillage du cours : installation de uv, uv init pour créer un projet, uv add pour ajouter une bibliothèque, uv run pour exécuter, uv sync pour reproduire l'environnement d'un autre. Le rôle de pyproject.toml et de uv.lock. VS Code : extensions Python et Jupyter, sélection de l'interpréteur du projet, carnets de notes.

  • Exercices. Traduction en Python de courts programmes C++ ou PHP fournis, puis réécriture pour qu'ils ressemblent à du vrai Python. Installation de uv et de VS Code, création d'un premier projet, ajout d'une bibliothèque et exécution.

  • Quiz. Différences C/C++/PHP/Python, résultat d'expressions simples, repérage de code écrit « en C++ déguisé ».

  • Travail à rendre. Traduire un programme plus long, livré sous forme de projet uv complet (pyproject.toml inclus), avec un court texte expliquant les choix d'écriture.

Séance 2 - Structures de données et compréhensions

  • Contenu du cours. Listes : indexation, découpage, index négatifs, méthodes courantes, mutabilité et effets de bord. Tuples et quand les préférer. Dictionnaires : accès, parcours, imbrication - la structure la plus utilisée en Python. Ensembles. Les compréhensions de listes et de dictionnaires : la façon idiomatique de transformer et filtrer des données. zip, enumerate, sorted avec clé.

  • Exercices. Comptage d'occurrences, filtrage et transformation d'une liste de dictionnaires, regroupement de données, réécriture de boucles en compréhensions.

  • Quiz. Choix de la bonne structure, résultat d'un découpage, lecture d'une compréhension, effets de bord sur une liste.

  • Travail à rendre. Traitement d'un petit jeu de données fourni sous forme de liste de dictionnaires : filtrage, regroupement, statistiques.

Séance 3 - Fonctions, modules et style Python

  • Contenu du cours. Définir une fonction, paramètres par défaut, arguments nommés, *args et **kwargs. Retours multiples. Portée des variables et pièges classiques. Docstrings et annotations de type. Les fonctions comme objets : passer une fonction en argument, lambda, map, filter, sorted(key=...) - indispensable pour comprendre le code des bibliothèques scientifiques. Organiser un projet en modules, import, if __name__ == "__main__".

  • Exercices. Écriture d'une petite boîte à outils réutilisable, tri d'une liste selon plusieurs critères, fonction qui prend une autre fonction en paramètre.

  • Quiz. Passage d'arguments, portée, lecture d'une lambda, résultat d'un sorted avec clé.

  • Travail à rendre. Restructurer le travail de la séance 2 en modules et fonctions documentées.

Séance 4 - Erreurs, fichiers et formats de données

  • Contenu du cours. Lire une pile d'appels et un message d'erreur. Les erreurs les plus fréquentes. try, except, else, finally, lever une exception. Quand traiter et quand laisser remonter. Lire et écrire un fichier texte, le bloc with, chemins avec pathlib, encodage. Le format CSV et le module csv. Le format JSON et le module json. Passer d'un fichier à une structure Python et l'inverse.

  • Exercices. Débogage de programmes cassés fournis par l'enseignant, lecture d'un CSV et calcul de statistiques, conversion CSV vers JSON, fiabilisation d'un chargement de fichier.

  • Quiz. Type d'erreur à partir d'un message, comportement d'un bloc try, modes d'ouverture, correspondance JSON/Python.

  • Travail à rendre. Un programme qui charge un fichier de données réel, le valide, signale proprement les lignes défectueuses et produit un rapport.

Séance 5 - Classes et lecture de code de bibliothèque

  • Contenu du cours. Classes en Python : __init__, self, attributs, méthodes, __str__ et __repr__. Ce qui diffère du C++ et du PHP : pas de private réel, pas de surcharge de méthode, attributs ajoutés dynamiquement. Héritage simple, rapidement. Puis l'objectif réel de la séance : savoir lire du code orienté objet qu'on n'a pas écrit. Anatomie d'une bibliothèque, lecture d'une documentation, sens du schéma objet = Classe(paramètres) puis objet.methode(données) qu'on retrouve partout en apprentissage automatique.

  • Exercices. Transformation d'une structure de données en classe. Prise en main guidée d'une bibliothèque tierce inconnue à partir de sa seule documentation.

  • Quiz. Rôle de self, différences avec le C++ et le PHP, lecture d'un extrait de code de bibliothèque.

  • Travail à rendre. Utiliser une bibliothèque non vue en cours pour résoudre un petit problème, en documentant la démarche de lecture de la documentation.

Séance 6 - NumPy : penser en tableaux

  • Contenu du cours. Pourquoi une liste Python ne suffit pas pour du calcul numérique. Le tableau NumPy : création, forme, type, dimensions. Indexation, découpage, indexation booléenne. Opérations élément par élément et diffusion (broadcasting). Fonctions d'agrégation et notion d'axe. Le changement de réflexe central : remplacer une boucle par une opération sur le tableau entier. Comparaison de performance mesurée en direct.

  • Exercices. Réécriture sans boucle de traitements écrits avec boucles, filtrage par condition, statistiques par ligne et par colonne, normalisation d'un tableau de données.

  • Quiz. Forme d'un tableau après opération, résultat d'une indexation booléenne, notion d'axe, repérage d'une boucle inutile.

  • Travail à rendre. Reprendre un traitement écrit à la séance 2 avec des boucles et le réécrire en NumPy, en comparant les temps d'exécution. Le sujet du projet final est distribué à cette séance.

Séance 7 - pandas : charger, nettoyer, explorer

  • Contenu du cours. Series et DataFrame. Charger un fichier CSV. Inspecter un jeu de données : dimensions, types, premières lignes, statistiques descriptives. Sélectionner des colonnes et des lignes, loc et iloc. Filtrer avec des conditions. Créer des colonnes calculées. Gérer les valeurs manquantes. Regrouper avec groupby et agréger. Trier. Pourquoi le nettoyage des données occupe la majorité du temps d'un projet d'IA.

  • Exercices. Exploration guidée d'un jeu de données réel : première lecture, repérage des anomalies, nettoyage, réponses à une série de questions par filtrage et regroupement.

  • Quiz. Différence entre loc et iloc, résultat d'un filtrage, lecture d'un groupby, traitement des valeurs manquantes.

  • Travail à rendre. Nettoyer un jeu de données volontairement sale fourni par l'enseignant et répondre à cinq questions d'analyse.

Séance 8 - Visualisation et chaîne complète

  • Contenu du cours. Bases de la visualisation avec Matplotlib : courbe, histogramme, nuage de points, titres et légendes. Choisir le bon graphique selon la question posée. Puis la synthèse : assembler une chaîne complète, du fichier brut au résultat présenté. Organisation d'un projet Python propre. Ce qui vous attend au cours d'intelligence artificielle et ce que vous avez déjà entre les mains pour l'aborder.

  • Exercices. Production de trois graphiques à partir du jeu de données de la séance 7 et justification du choix de chacun.

  • Quiz. Quiz récapitulatif couvrant l'ensemble du cours.

  • Travail à rendre. Finalisation et remise du projet final.

8. Règles de fonctionnement

Présence. La présence est nécessaire : le quiz se fait en salle et n'est pas rattrapable, sauf absence justifiée signalée à l'avance.

Remise des travaux. Les travaux se déposent sur Classmoji, sous forme de dépôt Git, avant le début de la séance suivante. Chaque travail est un dépôt privé à votre nom, et on remet en fermant l'issue du travail. Le mode d'emploi complet est dans le module 0.

Vous disposez de trois tokens pour le semestre. Un token repousse une échéance de 24 heures, sans justification à fournir : vous le posez vous-même. Ils existent pour les coupures de courant et les connexions perdues, qui ne sont pas des négligences. Une fois les trois tokens dépensés, tout retard entraîne une pénalité de 10 % par jour entamé, jusqu'à trois jours. Au-delà, le travail n'est plus accepté.

Entraide et plagiat. Discuter d'un problème entre étudiants est encouragé. En revanche, le code que vous remettez doit être écrit par vous et vous devez pouvoir l'expliquer. Copier le travail d'un autre, ou le laisser copier, expose aux sanctions prévues par le règlement de l'établissement. En cas de doute, l'enseignant peut demander à l'étudiant d'expliquer son code.

Intelligence artificielle. Les assistants d'IA sont autorisés pour comprendre une notion, expliquer une erreur ou explorer une piste. Ils ne sont pas autorisés pour produire le code que vous remettez. Tout usage doit être mentionné en commentaire en tête du fichier. Rappel utile : le quiz et le projet se défendent en salle, sans assistance.

Outillage. Le cours utilise deux outils, et deux seulement : uv pour gérer Python, les projets et les bibliothèques, et VS Code comme éditeur. Ce choix est volontaire : moins de temps passé sur l'outillage, plus de temps sur le langage. Tous les travaux sont remis sous forme de projet uv.

Git et GitHub servent uniquement à la remise des travaux. Ce ne sont pas des outils du cours : ils ne figurent dans aucun résultat d'apprentissage et ne sont évalués nulle part. Le module 0 en donne le strict nécessaire, et une voie entièrement dans le navigateur existe pour ceux qui n'ont pas d'ordinateur.

Matériel. Un appareil connecté est nécessaire à chaque séance : ordinateur portable, ou à défaut téléphone ou tablette. Aucun étudiant n'est pénalisé parce qu'il ne possède pas d'ordinateur. La section 9 détaille les solutions disponibles, et les travaux sont conçus pour être réalisables dans chacune d'elles.

9. Outils, accès au matériel et ressources

9.1 Trois façons de travailler

Le cours ne suppose pas que vous possédiez un ordinateur. Trois configurations sont acceptées, et toutes les trois permettent de suivre les huit séances et de rendre les travaux. Choisissez la vôtre à la séance 1, avec l'enseignant.

Option A - Ordinateur personnel avec uv et VS Code (configuration de référence)

  • uv, depuis https://docs.astral.sh/uv - une seule installation à faire

  • uv installe lui-même la version de Python nécessaire : rien à télécharger séparément depuis python.org

  • VS Code, avec les extensions Python et Jupyter

  • Les bibliothèques du cours s'ajoutent au projet avec uv add numpy pandas matplotlib

  • Avantage : vous travaillez hors ligne, et l'enseignant peut distribuer un projet que vous reproduisez à l'identique avec uv sync

Option B - Google Colab, depuis un navigateur

  • Adresse : https://colab.research.google.com - gratuit, un compte Google suffit

  • Rien à installer : Python, NumPy, pandas, Matplotlib et Jupyter sont déjà présents

  • Fonctionne sur ordinateur, sur tablette et sur téléphone

  • Les carnets s'enregistrent automatiquement sur Google Drive et se rendent par lien partagé

  • Limite : il faut une connexion internet pendant toute la durée du travail, et uv n'y est pas utilisé - les bibliothèques y sont déjà installées

Option C - Téléphone, hors connexion

  • Pydroid 3 sur Android : interpréteur Python complet, fonctionne sans internet, permet d'installer NumPy, pandas et Matplotlib

  • Pythonista sur iOS, ou Google Colab en mode connecté pour les appareils iOS

  • Limite : la saisie de code sur un petit écran est lente. Cette option convient pour les exercices courts et la révision, moins pour le projet final

Mesures d'accompagnement

  • Les étudiants sans ordinateur travaillent en binôme pendant les exercices en salle

  • La salle machine est ouverte [créneaux à préciser] pour le travail personnel et le projet

  • Tout travail est accepté sous forme de carnet Colab partagé, au même titre qu'un projet uv

  • Les postes de la salle machine sont équipés de uv et de VS Code

  • L'installation, quelle que soit l'option, se fait en séance 1 avec l'enseignant
