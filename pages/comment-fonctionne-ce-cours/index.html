Où se trouve quoi

Tout le cours vit ici, organisé en modules. Un module par séance, plus celui-ci.

Un module apparaît le jour de sa séance et ne disparaît plus. Vous y trouverez, dans cet ordre :
Les diapositives Ce qui a été projeté pendant la séance
Le support de cours Le contenu de la séance, rédigé pour être lu seul. C'est le document à conserver
Les exercices Ceux faits en salle, avec leurs variantes pour travailler sans ordinateur
Le travail à rendre L'énoncé, les contraintes, la grille d'évaluation
Le quiz Passé en salle, noté
Les dépôts Un par travail : c'est là que vous codez et que vous rendez

Si un module n'est pas encore visible, c'est qu'il n'a pas eu lieu. Ce n'est pas une erreur de votre côté.

Le déroulé d'une séance

Les huit séances suivent exactement la même structure. Il n'y a pas de surprise.

Temps Quoi
55 min Le cours. Vous codez en même temps que l'enseignant, sur votre machine
35 min Les exercices. Seul ou à deux, corrigés en classe
15 min Le quiz, noté
10 min Le travail à rendre est présenté. Vous le terminez chez vous

Venez avec de quoi coder : un ordinateur portable, ou à défaut un téléphone ou une tablette. Vous ne serez pas pénalisé si vous n'avez pas d'ordinateur lisez la page « Travailler sans ordinateur » de ce module.

Comment on rend un travail

C'est la seule mécanique nouvelle du cours, et elle est toujours la même.

  1. Le travail vous arrive sous forme de dépôt privé à votre nom, créé automatiquement. Vous recevez un lien
  2. Le dépôt contient l'énoncé, les fichiers de départ, et une issue qui décrit ce qui est attendu
  3. Vous travaillez et vous envoyez votre code au fur et à mesure
  4. Vous fermez l'issue. C'est ça, remettre. L'heure de fermeture est l'heure de remise
  5. L'enseignant ouvre une pull request de retour avec ses remarques, attachées aux lignes de votre code

Tout ceci est expliqué pas à pas dans la page « Git et GitHub » de ce module. Lisez-la avant la séance 1 : c'est la seule vraie préparation que le cours vous demande.

La règle qui explique tout le reste : on ne rend pas un fichier, on rend un projet complet. Un programme Python vient avec la liste des bibliothèques dont il a besoin et leurs versions exactes. C'est ce qui permet à quelqu'un d'autre de reconstruire votre environnement et d'obtenir votre résultat. Un .py seul ne vaut rien.

Les six meilleurs quiz sur huit : une absence, une panne de courant ou une mauvaise journée ne se paient pas. C'est prévu, ne vous inquiétez pas au premier accident.

Ce qui est regardé dans chaque travail, et qui vaut autant que « ça marche » : le code est lisible et écrit à la manière de Python, les structures choisies sont adaptées, les cas d'erreur sont pris en compte, la démarche est expliquée.

Les retards, et les tokens

Vous disposez de trois tokens pour le semestre. Un token repousse une échéance de 24 heures, sans avoir à écrire à qui que ce soit ni à vous justifier. Vous le posez vous-même sur le travail concerné.

Ils existent pour une raison précise : une coupure de courant de deux jours ou une connexion perdue n'est pas une négligence, et vous ne devriez pas avoir à en faire la demande - souvent, vous ne pouvez pas non plus.

Une fois vos trois tokens dépensés, la règle du plan de cours s'applique : −10 % par jour entamé, jusqu'à trois jours, puis le travail n'est plus accepté.

Conseil : gardez-en au moins un pour la fin du semestre, quand le projet final et le reste de vos cours tomberont en même temps.

Entraide, plagiat, et assistants d'IA

Discuter d'un problème entre vous est encouragé. C'est comme ça qu'on apprend, et c'est comme ça qu'on travaille ensuite.

Le code que vous remettez doit être écrit par vous, et vous devez pouvoir l'expliquer. Copier le travail d'un autre, ou le laisser copier, expose aux sanctions du règlement de l'établissement. En cas de doute, l'enseignant peut vous demander d'expliquer votre code et les quiz se passent en salle, sans assistance.

Les assistants d'IA sont autorisés pour comprendre une notion, expliquer une erreur, explorer une piste. Ils ne le sont pas pour produire le code que vous rendez. Tout usage se mentionne en commentaire en tête de fichier. Une ligne suffit :

Python
12
# Usage d'IA : aucun
# ou : Usage d'IA : j'ai demandé une explication de la fonction zip. Le code est de moi.

Ce n'est pas un piège. Déclarer un usage honnête ne coûte aucun point. Ne pas le déclarer en coûte deux.

Avant la séance 1

Cinq choses, dans cet ordre. Comptez une heure en tout.

  1. Lire le plan de cours - c'est le document de référence de l'année
  2. Lire « Git et GitHub » et créer votre compte
  3. Lire « Installer son environnement » et installer uv et VS Code
  4. Si vous n'avez pas d'ordinateur : lire « Travailler sans ordinateur » et préparer votre solution
  5. Récupérer le dépôt d'entraînement 00-prise-en-main, y faire un commit, fermer son issue

Le dépôt d'entraînement n'est pas noté. Il sert à ce que votre première remise ne soit pas celle qui compte.

Si quelque chose bloque, ne restez pas dessus la veille au soir : écrivez dans l'issue du dépôt d'entraînement. C'est fait pour ça, et l'enseignant y répond avant la séance.
