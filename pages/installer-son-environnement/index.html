Pourquoi le faire avant

La séance 1 consacre douze minutes à l'installation. Douze minutes suffisent pour une salle où tout se passe bien, et une salle où tout se passe bien, ça n'existe pas : il y a toujours une connexion coupée en plein téléchargement, un terminal non relancé, un antivirus qui s'interpose.

Si vous arrivez avec un environnement qui fonctionne, ces douze minutes servent à autre chose - et vous ne passez pas la séance à regarder une barre de progression pendant que le cours avance.

Si vous n'y arrivez pas, ce n'est pas grave. Venez quand même, on le fera ensemble. Mais essayez : c'est bien plus confortable d'échouer chez soi que devant une classe entière.

Deux outils, et deux seulement
uv S'occupe de tout ce qui concerne Python : la version du langage, vos projets, les bibliothèques
VS Code L'endroit où vous écrivez le code

Vous n'avez pas besoin d'installer Python. uv s'en charge, et il installera la bonne version au premier lancement. N'allez pas sur python.org : c'est la source de la moitié des problèmes du premier mois.

1. Installer uv

macOS et Linux

Dans un terminal :

Terminal
bash
1
curl -LsSf https://astral.sh/uv/install.sh | sh

Windows

Dans PowerShell :

Terminal
bash
1
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

Puis, dans les deux cas

Fermez votre terminal et rouvrez-le. Sans ça, la commande ne sera pas trouvée - c'est l'erreur numéro un, et elle n'a rien à voir avec une installation ratée.

Terminal
bash
1
uv --version

Si un numéro de version s'affiche, c'est fait.

2. Installer VS Code

Téléchargez-le sur code.visualstudio.com et installez-le.

Puis, dans VS Code, ouvrez le panneau des extensions (l'icône des quatre carrés dans la barre de gauche) et installez :

  • Python (éditeur Microsoft)
  • Jupyter (éditeur Microsoft)

C'est tout. Ne chargez pas dix extensions Python : elles se marchent dessus et produisent des messages contradictoires.

3. Créer votre premier projet

Dans un terminal, dans le dossier où vous voulez ranger vos projets :

Terminal
bash
123
uv init prise-en-main
cd prise-en-main
uv run main.py

Vous devriez voir s'afficher quelque chose comme :

Code
12
Creating virtual environment at: .venv
Hello from prise-en-main!

Ce qui vient de se passer. uv init a créé un projet. Le premier uv run a téléchargé Python si vous ne l'aviez pas, créé l'environnement isolé du projet, puis exécuté le programme. Les fois suivantes, ce sera immédiat.

Ajoutez maintenant une bibliothèque, pour vérifier que ça marche aussi :

Terminal
bash
12
uv add numpy
uv run main.py

Regardez le fichier pyproject.toml : numpy y est apparu. La bibliothèque est enregistrée dans le projet, pas quelque part sur votre machine. C'est le point important, et on y reviendra en séance.

4. Le réglage qu'on oublie toujours

Dans VS Code :

  1. Ouvrez le dossier du projet, pas le fichier seul. Fichier → Ouvrir le dossier, puis prise-en-main
  2. Ouvrez la palette de commandes - Ctrl+Maj+P, ou Cmd+Maj+P sur Mac
  3. Tapez Python: Select Interpreter
  4. Choisissez celui dont le chemin contient .venv

Faites-le. Si vous sautez cette étape, VS Code vous dira qu'une bibliothèque est introuvable alors qu'elle est parfaitement installée, et vous chercherez pendant vingt minutes. C'est le problème le plus fréquent du cours, et le plus facile à éviter.

5. La règle qui vous évitera la moitié des ennuis

On lance toujours uv run fichier.py. Jamais python fichier.py.

La seconde commande utilise un Python quelconque de votre machine - pas celui de votre projet, pas celui qui a vos bibliothèques. Elle marche parfois, échoue souvent, et quand elle échoue le message d'erreur ne dit pas pourquoi.

Prenez le réflexe dès aujourd'hui, sur ce projet d'essai.

Les cinq commandes du cours

Vous n'en apprendrez pas d'autres cette année.

Commande Ce qu'elle fait
uv init nom Crée un projet
uv add bibliotheque Ajoute une bibliothèque au projet
uv run fichier.py Exécute un fichier dans l'environnement du projet
uv sync Reconstruit l'environnement à partir du projet
uv python list Montre les versions de Python disponibles

Si ça coince

Symptôme Cause Quoi faire
uv: command not found Terminal non relancé après l'installation Fermez le terminal, rouvrez-le. Si ça persiste, redémarrez la machine
Le téléchargement s'arrête en cours Connexion coupée, ou proxy Relancez la même commande : elle reprend. Sinon, voyez l'enseignant, il aura une clé USB
ModuleNotFoundError alors que la bibliothèque est installée Interpréteur non sélectionné dans VS Code, ou python utilisé au lieu de uv run Refaites l'étape 4, puis relancez avec uv run
VS Code ne trouve pas le projet Vous avez ouvert le fichier, pas le dossier Fichier → Ouvrir le dossier
Windows refuse d'exécuter le script Politique d'exécution PowerShell La commande donnée plus haut contient déjà -ExecutionPolicy ByPass. Vérifiez que vous l'avez copiée en entier

Rien ne marche ? Écrivez dans l'issue du dépôt 00-prise-en-main, en disant votre système d'exploitation et en recopiant le message d'erreur en entier. C'est fait pour ça, et vous obtiendrez une réponse avant la séance.
