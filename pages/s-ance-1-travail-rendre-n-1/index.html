À remettre avant le début de la séance 2

Résultats d'apprentissage évalués : RA1, RA2 — noté sur 20

Ce qu'on vous demande, en trois phrases

Vous recevez le même programme dans deux langages, C++ et PHP, d'une quarantaine de lignes chacun. Lisez celui que vous connaissez, ignorez l'autre. Vous devez le réécrire en Python — pas le traduire mot à mot, mais l'écrire comme on écrit en Python. Vous remettez un projet uv complet et un court texte qui explique cinq de vos choix.

Comptez deux heures. Ce n'est pas un travail difficile ; c'est un travail où le style compte autant que le résultat.

int main() {
    string jours[] = {"lundi", "mardi", "mercredi", "jeudi",

    double temperatures[] = {31.2, 29.8, 33.5, 35.1, 30.0, 28.4, 32.7};

    double minimum = temperatures[0];
    int nbChauds = 0;

    for (int i = 0; i < taille; i++) {
        somme = somme + temperatures[i];
        if (temperatures[i] > maximum) {
            maximum = temperatures[i];
        }
        if (temperatures[i] < minimum) {
            minimum = temperatures[i];
        }
        if (temperatures[i] >= seuil) {
            nbChauds = nbChauds + 1;
        }
    }

    double moyenne = somme / taille;

    cout << "--- Releve de la semaine ---" << endl;
    for (int i = 0; i < taille; i++) {
        string marque = "";
        if (temperatures[i] >= seuil) {
            marque = " (chaud)";
        }
        cout << (i + 1) << ". " << jours[i] << " : "
             << temperatures[i] << marque << endl;
    }

    cout << "Moyenne : " << moyenne << endl;
    cout << "Minimum : " << minimum << " / Maximum : " << maximum << endl;
    cout << "Jours au-dessus du seuil : " << nbChauds << endl;
    return 0;
}

$jours = ["lundi", "mardi", "mercredi", "jeudi",

$seuil = (float) trim(fgets(STDIN));

$minimum = $temperatures[0];

    if ($temperatures[$i] > $maximum) {

    if ($temperatures[$i] < $minimum) {

    if ($temperatures[$i] >= $seuil) {
        $nbChauds = $nbChauds + 1;
    }
}

$moyenne = $somme / count($temperatures);

echo "--- Releve de la semaine ---\n";
for ($i = 0; $i < count($jours); $i++) {
    $marque = "";
    if ($temperatures[$i] >= $seuil) {

    echo ($i + 1) . ". " . $jours[$i] . " : " . $temperatures[$i] . $marque . "\n";
}

echo "Moyenne : " . $moyenne . "\n";
echo "Minimum : " . $minimum . " / Maximum : " . $maximum . "\n";
echo "Jours au-dessus du seuil : " . $nbChauds . "\n";

Quatre différences avec le programme d'origine, voulues :

  1. Les accents. Le programme fourni écrit « Releve » et « degres » ; votre version écrit « Relevé » et « degrés ».
  2. La moyenne s'affiche avec une seule décimale. Le C++ affichait 31.5286, le PHP 31.528571428571.
  3. Les températures gardent leur décimale : votre version écrit 30.0 là où le C++ et le PHP écrivent 30. C'est Python qui a raison ici — c'est un nombre décimal, il s'affiche comme tel. N'ajoutez aucun formatage pour l'obtenir, Python le fait seul.
  4. Les autres nombres s'affichent tels quels, sans mise en forme.

Testez aussi avec les seuils 28 et 40. Le premier doit marquer les sept jours, le second aucun. Ces deux cas seront exécutés à la correction.

Les contraintes d'écriture

Ce sont elles qui font la différence entre 10 et 18.

Ce qui est exigé
1 Aucun for i in range(len(...)). Chaque occurrence coûte 1 point
2 Les quatre calculs — somme, minimum, maximum, moyenne — utilisent les outils que Python fournit. Une boucle qui recalcule à la main ce que sum, min ou max fait déjà est comptée comme une erreur de style
3 Les deux listes se parcourent en parallèle. Vous avez vu l'outil en cours
4 Toutes les sorties passent par des f-strings. Aucune concaténation avec +
5 snake_case, quatre espaces d'indentation, espaces autour des opérateurs
6 Aucune variable ne porte le nom d'un outil du langage — pas de max, min, sum, list, type

Une chose ne peut pas disparaître. Un des quatre calculs de la boucle d'origine n'a pas d'équivalent tout fait en Python avec ce que vous savez aujourd'hui : il vous restera une boucle. Trouvez laquelle, gardez-la, et écrivez-la proprement. Ne cherchez pas sur internet une écriture plus courte : elle existe, elle s'apprend à la séance 2, et elle ne rapportera pas de point ici.

Et vous fermez l'issue du travail. C'est ça, remettre : l'heure de fermeture est l'heure de remise. Tant que l'issue est ouverte, le travail n'est pas rendu, même si votre code est en ligne.

Faites plusieurs commits pendant votre travail, pas un seul à la fin.

Le .venv/ ne doit pas partir dans le dépôt. uv le marque lui-même comme ignoré, vous ne risquez donc rien — mais prenez quand même le réflexe de regarder ce que git status affiche avant de commiter. Si vous y voyez des dizaines de fichiers que vous n'avez pas écrits, arrêtez-vous et demandez.

Pour vérifier que votre remise est complète : ouvrez la page du dépôt sur GitHub. Ce que vous y voyez est exactement ce que l'enseignant voit.

Si vous travaillez sur Google Colab. Remettez un carnet nommé tp1-nom-prenom, déposé dans le dépôt ou partagé par lien dans l'issue. Une première cellule de texte tient lieu de NOTES.md, une deuxième cellule contient le programme. Le seuil, que vous ne pouvez pas saisir confortablement, est écrit en variable en tête de programme — signalez-le dans vos notes. Signalez aussi dans l'issue que c'est votre voie. Même barème, à un point près : les 2 points « projet uv complet » deviennent 2 points « carnet propre, exécutable de haut en bas sans erreur ».

Le contenu de NOTES.md

Cinq paragraphes courts, un par choix. Pour chacun : ce que faisait le programme d'origine, ce que vous avez écrit, pourquoi.

Les points-virgules. Le C++ comme le PHP en mettent à chaque fin d'instruction. Je les ai tous supprimés : en Python, le retour à la ligne suffit. Python les tolère, mais un code qui en contient se repère immédiatement comme du code traduit.

Trois conseils

  1. Traduisez d'abord littéralement, faites tourner, puis réécrivez. C'est exactement l'exercice 1 de la séance, en plus long. Ne sautez pas la première étape en croyant gagner du temps.
  2. Relisez la contrainte n° 2 après avoir fini. Le réflexe « je calcule la somme dans une boucle » survit à tout, et c'est la première chose qui sera regardée.
  3. Écrivez NOTES.md en dernier, mais notez vos choix au fur et à mesure. Reconstituer après coup pourquoi on a fait quelque chose est plus long que de l'écrire sur le moment.
