Le principe

Ce cours ne suppose pas que vous possédiez un ordinateur. Aucune opération du cours n'en exige un : lire les supports, écrire du code, rendre un travail, lire les remarques de l'enseignant - tout se fait depuis un navigateur, y compris sur téléphone.

Ce n'est pas une version au rabais. Vous rendez le même travail, il est évalué sur la même grille, et rien dans la note ne dépend de votre matériel. La seule chose que vous perdez, c'est du confort de saisie, et il existe des façons de le compenser.

Dites à l'enseignant, à la séance 1, dans quelle situation vous êtes. Pas pour être traité différemment : pour qu'il prévoie les créneaux de salle machine et les binômes en conséquence.

Rendre un travail depuis un navigateur

Aucune commande Git. Cinq étapes, sur la page de votre dépôt GitHub.

  1. Ouvrez le lien du dépôt que vous avez reçu. Vous voyez la liste des fichiers et l'énoncé
  2. Lisez l'issue attachée au dépôt : c'est là qu'est décrit ce qui est attendu
  3. Écrivez votre code dans Colab, ou dans Pydroid, ou directement sur GitHub en cliquant sur un fichier puis sur l'icône du crayon
  4. Déposez vos fichiers : bouton Add file → Upload files, glissez vos fichiers, écrivez un court message, puis Commit changes
  5. Fermez l'issue. C'est ça, remettre

Vérifiez toujours que vos fichiers apparaissent bien dans la liste du dépôt. Ce que vous voyez sur cette page est exactement ce que l'enseignant voit.

Pour lire les remarques de l'enseignant : onglet Pull requests du dépôt. Ses commentaires sont attachés aux lignes concernées de votre code.

Astuce. Sur la page d'un dépôt, appuyez sur la touche . (le point) : GitHub ouvre un éditeur complet dans votre navigateur, avec l'arborescence des fichiers. C'est presque VS Code, sans rien installer. Ça marche aussi sur tablette.

Rendre un travail depuis Colab

Si vous travaillez en carnet Colab plutôt qu'en projet uv :

  1. Nommez votre carnet comme l'énoncé le demande - en général tpN-nom-prenom
  2. Téléchargez-le : Fichier → Télécharger → .ipynb
  3. Déposez le .ipynb dans votre dépôt, comme n'importe quel fichier
  4. Ou, si l'énoncé l'autorise, remettez simplement le lien de partage du carnet dans l'issue

Dans un carnet Colab, rendez visible ce qu'un projet uv aurait montré : une première cellule de texte qui liste les bibliothèques utilisées et remplace le pyproject.toml, et un carnet qui s'exécute de haut en bas sans erreur. C'est ce qui sera vérifié. Avant de rendre : Exécution → Redémarrer et tout exécuter, et regardez que ça passe.

Le point à ne pas laisser passer : uv

Le premier résultat d'apprentissage du cours - RA1 - porte sur la mise en place d'un projet Python avec uv. Sur Colab, vous ne pratiquerez pas ça.

Ce n'est pas une raison pour l'ignorer : il est évalué dans les quiz, et il vous servira dès que vous aurez accès à une machine.

La solution prévue : un créneau en salle machine autour de la séance 1, pour que vous fassiez l'installation et créiez un projet uv au moins une fois, de vos mains. Une heure suffit. Demandez le créneau à l'enseignant à la séance 1, il est prévu au calendrier.

Les mesures du cours

Elles s'appliquent sans que vous ayez à les demander :

  • Binômes pendant les exercices en salle - personne ne reste sans machine pendant les 35 minutes d'exercices
  • La salle machine est ouverte pour le travail personnel et le projet, aux créneaux annoncés en séance
  • Les postes de la salle machine ont déjà uv et VS Code installés
  • Tout travail est accepté sous forme de carnet Colab, au même titre qu'un projet uv
  • Trois tokens de report pour le semestre, à poser sans justification - ils existent pour les coupures de courant et les connexions perdues
